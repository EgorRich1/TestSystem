# Тесты: подготовка к экзаменам

Веб-приложение для самопроверки по тестам из Word-файлов (.docx). Работает целиком в браузере, без сервера.
React + TypeScript + Vite + Tailwind.

В комплекте два теста: **«Тесты Дерма 2026»** (764 вопроса, из них 11 — по картинке) и **«Тесты Терапия 2026»** (624 вопроса).

## Запуск

Нужен Node.js 20+.

```bash
npm install
```

```bash
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://localhost:5173).

### Сборка

```bash
npm run build
```

Готовый сайт появится в папке `dist/`. Это статические файлы: их можно открыть через любой веб-сервер
(`npm run preview`, GitHub Pages, Netlify и т. п.). Пути относительные, так что подпапка тоже подойдёт.
Открыть `dist/index.html` двойным щелчком не получится: браузер не даст загрузить .docx по `file://`.

### Тесты и отчёт о разборе

```bash
npm test
```

```bash
npm run report
```

`npm test` запускает юнит-тесты парсера (`src/parser/parser.test.ts`), в том числе на настоящих файлах.
`npm run report` разбирает файлы и пишет `PARSE_REPORT.md` — список вопросов, которые стоит проверить вручную.
Тот же отчёт есть в приложении: ссылка «Проблемы разбора» на главном экране.

## Как пользоваться

1. Выберите тест (или загрузите свой .docx).
2. Выберите режим: **все вопросы** (по порядку файла, можно перемешать) или **150 случайных**.
3. Отвечайте. Один правильный ответ — переключатели, несколько — флажки.
   «Проверить» подсвечивает правильные ответы зелёным, ваши ошибки — красным, пропущенные — «пропущен».
   Вопрос с несколькими ответами засчитывается, только если выбран ровно правильный набор.
4. В конце — процент, список ошибок и кнопка «Повторить только ошибки».

Прогресс сохраняется в браузере (localStorage): после перезагрузки страницы тест можно продолжить.

Клавиши: **1–9** — выбрать вариант, **Enter** — проверить / дальше, **← →** — листать вопросы.
В вопросах по картинке: **Enter** — показать ответ, **1** — «верно», **2** — «ошибся».
В шапке: размер шрифта (A− / A+) и тема (системная / светлая / тёмная).

## Как добавить новый тест

**Способ 1 — загрузить в приложении.** На главном экране «Загрузить свой .docx». Файл разбирается прямо в браузере
и запоминается в нём (если помещается в localStorage). Удалить — кнопка «Удалить» рядом с названием.

**Способ 2 — встроить в приложение.**

1. Положите файл в `public/tests/`, например `public/tests/hirurgia-2026.docx`.
2. Добавьте строку в `BUNDLED` в `src/lib/tests.ts`:
   ```ts
   { key: 'hirurgia-2026', title: 'Тесты Хирургия 2026', bundled: true, url: './tests/hirurgia-2026.docx' },
   ```
3. Проверьте разбор: `npm run report -- public/tests/hirurgia-2026.docx` и откройте `PARSE_REPORT.md`.

### Какой формат понимает парсер

Формат как в выгрузке из Moodle:

```
12. Текст вопроса (может быть на нескольких строках)
Выберите один ответ:            ← или «Выберите один или несколько ответов:»
вариант 1
вариант 2   ← правильный: выделен
вариант 3
```

- Номер вопроса: `12.`, `12)`, `12 -` или `12 Текст`. Можно без номера, если есть строка «Выберите…».
- Если строк «Выберите…» в файле нет вовсе, вопросы ищутся по номерам, а варианты — строки до следующего номера
  (метки `а)`, `б)`, `A.`, `1)` убираются, если они есть у всех вариантов).
- **Правильный ответ** — вариант, оформление которого отличается от соседних: выделение цветом (highlight), заливка,
  значок ✅/✔, жирный шрифт, цвет, подчёркивание, курсив. Оформление, общее для всех вариантов, не учитывается.
  Если выделены *все* варианты, а в остальном файле то же выделение отмечает ответы, все варианты считаются правильными.
- **Картинки** (JPG, PNG, GIF, WebP, SVG) встраиваются в вопрос:
  картинка в тексте вопроса или между вопросом и «Выберите…» показывается под текстом вопроса,
  картинка сразу после варианта ответа — внутри этого варианта (её можно увеличить нажатием).
- **Вопрос только из картинки** (`728 - ` и скриншот, без текстовых вариантов) импортируется как «вопрос по картинке»:
  варианты ответа видны на самой картинке, поэтому проверка — самооценкой («Я ответил верно» / «Я ошибся»).
  Если на скриншоте Moodle внизу есть жёлтая плашка «Правильный ответ: …», она скрыта до нажатия «Показать ответ».
  Отметки ✓/✗ прошлой попытки на скриншоте скрыть нельзя.
- Красные подчёркнутые строки (или стили «Заголовок») считаются названиями разделов.
- Белый (невидимый) и скрытый текст игнорируется.

## Как устроен парсер

`src/parser/`:

- `docxXml.ts` — читает `word/document.xml` и `word/styles.xml` через JSZip + DOMParser. Для каждого фрагмента
  текста (`<w:r>`) вычисляет итоговое оформление: стиль документа → стиль абзаца → стиль символа → `<w:rPr>`,
  плюс заливка абзаца из `<w:pPr>`. Абзацы режутся на строки по `<w:br/>`.
- `questions.ts` — собирает вопросы вокруг строк «Выберите…», склеивает перенесённые строки ответов,
  определяет правильные ответы по правилу «отличается от соседей» и составляет отчёт.
- Вариант считается выделенным, если выделено больше половины его текста.

Результат для каждого вопроса: `{ id, text, options: [{ id, text, isCorrect, images? }], type: 'single' | 'multiple' | 'self', images? }`,
плюс `number` (номер в файле) и `section` (раздел). `images` — ключи вида `media/image1.jpg`; сами картинки
лежат в `ParsedTest.images` как data:-URL (берутся только те, что используются в вопросах).
